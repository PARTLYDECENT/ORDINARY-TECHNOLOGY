=========================================================
      GENESIS KERNEL: SDF ENGINE PROJECT OUTLINE
=========================================================

1. CURRENT ARCHITECTURE
---------------------------------------------------------
The "Genesis Kernel" is a modular, GPU-driven procedural landscape generation engine utilizing Signed Distance Fields (SDFs) and Raymarching. 

- Project Structure:
  - entropy2.html  : Entry point, establishes the canvas and imports the modular JS.
  - renderer.js     : Handles the Three.js ecosystem, rendering loop, WebGL interaction, and connects the Physics models to the Shader Uniforms.
  - translator.js   : Constructs the fragment shader dynamically, pulling mathematically defined SDF logic from rules.js and linking input uniforms.
  - rules.js        : The core logical dictionary. Contains the fundamental layout of space, distance operators (smin), primitive shapes (sdBox, sdGyroid), and high-level semantic states (Iron, Splat, Flora).
  - controls/
    - player.js     : Dedicated CPU-side physics, providing momentum, friction, gravity, walking and jumping logic.
    - camera.js     : Manages 3D view angles utilizing Pointer Lock APIs to create a seamless FPS exploration view.


2. CORE PHILOSOPHY & ADVANTAGES
---------------------------------------------------------
- Infinite Resolution: Space is evaluated per-pixel mathematically instead of using localized polygonal meshes. Detail is technically limitless.
- Semantic State Blending: Materials and shapes can seamlessly morph into entirely different forms without traditional model-swapping or LOD popping.
- Micro-Footprint: Generates gigabytes worth of visual data dynamically on the GPU from a few kilobytes of code.
- GPU Bound: The CPU handles almost nothing but the player's basic position. The graphic card's 1000+ cores handle lighting, shadows, physics interaction, and rendering simultaneously.


3. POSSIBLE FUTURE DIRECTIONS (THE ROADMAP)
---------------------------------------------------------
A. VISUALS AND RENDERING
   - Soft Shadows & Ambient Occlusion: Utilize the inherent nature of SDFs to cheaply generate visually stunning and realistic lighting interactions.
   - Subsurface Scattering: Deepen the organic states (like the Flora) by implementing realistic light bleed and scattering.
   - Depth of Field: Simulate a physical camera lens by blurring distant objects based on the returned raymarching depth.
   - Additional State Dimensions: Introduce highly complex fractal states (Mandelboxes) or fully procedural architectural states (cities/megastructures).

B. GAMEPLAY AND INTERACTION
   - Precise CPU/GPU Physics Bridge: Currently, floor collision is a naive Y-barrier on the CPU. A dedicated pipeline to read and approximate SDF data back on the CPU could allow for true wall bumping and slope climbing.
   - SDF Projectiles & Weapons: A mechanic that fires raycasted "weapons" that interact with the SDF world, mathematically subtracting matter (destruction) or adding matter (creation).
   - Entities & AI: Incorporating boids or procedural creatures directly into the shader and evaluating them within the raymarching loop, creating swarms that morph as they pass through the semantic waves.

C. EXTENSIONS AND TOOLS
   - Node-Based "Rules" Editor: A UI extension that allows creating new shapes and combinations in `rules.js` via a visual interface, accelerating prototyping.
   - Multiplayer Node Synchronization: Because the world is deterministic, multiplayer is incredibly cheap. We only need to sync player X/Y/Z positions over WebSockets. The entire universe remains locally generated.
   - WebXR Port: Transitioning the camera from a traditional 2D display to a full VR/AR stereoscopic projection.
